

### Mock hardware (I3-005)

`hardware/mock/` (library `kritva_hardware_mock`, depends only on `kritva::hardware`) is shared by the tests and the demo. `MockImuDevice` has `acceleration` and `angular_velocity` endpoints and `MockMotorDevice` has `command` and `position` endpoints over one simulated joint. Data is deterministic: a documented formula per sample with virtual timestamps. Every mock endpoint takes a failure schedule from configuration (`fail_after_ops`/`fail_after_writes`: one transient `INTERNAL_ERROR` after N successful operations; `fault_after_ops`/`fault_after_writes`: the endpoint enters FAULT after the Nth) and offers `inject_fault()`, `fail_next_operation()` and `degrade()`. Sensor settings are `start` and `step` (integers); the motor takes `min_rad_s`/`max_rad_s` (integers; `set_limits()` for fractions); the position endpoint takes `initial`. The motor is fail-safe: commands are validated before they are applied, a rejected or failed write changes nothing, and the joint velocity is zero at initialize, stop and shutdown and whenever the command endpoint is not RUNNING (a faulted motor stops). The mocks pass the same conformance suite as any endpoint.
